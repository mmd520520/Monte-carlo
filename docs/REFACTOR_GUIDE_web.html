01 · 背景

一分钟看懂蒙特卡洛

光照进皮肤以后不走直线。它会不停地被细胞和纤维弹开、拐弯，一部分被吸收，一部分又从皮肤表面跑出去。光到底到了哪里、到了多少，没法直接测，所以要算。

蒙特卡洛（Monte Carlo，简称 MC）的办法很朴素：在电脑里放出成千上万个“光子”，每个光子按组织的性质随机走一段、留下一点能量、换个方向，直到被吸收完或者跑出去。把所有光子留下的能量加起来，就知道光在组织里是怎么分布的。光子放得越多，结果越稳定。

光少光多

示意模型：空气、表皮、真皮和一根血管。参数是为了演示调过的，不是真实值。真实的仿真在仓库的 legacy/matlab/2demo 里。

看血管（虚线圆）：血液吸收强，它下面明显暗一块。最后一行永远是 100%，这就是“能量守恒自检”，真实代码每次运行都会做。

一个光子的一生

  1. 发射在光斑里随机取一点，照进组织。表面直接反射掉的那部分先扣掉。
  2. 走一段随机决定这次走多远。组织越“浑浊”（散射越强），平均走得越短。
  3. 留一点按吸收的强弱，把一部分能量留在所在的小方格里。
  4. 拐个弯按散射规律换一个方向。人体组织多数时候只是稍微偏一点，不会掉头。
  5. 轮盘赌能量太小的光子，十分之一的机会继续（能量乘 10），其余直接结束。平均下来能量不多不少，又省了计算。

上期内部分享（10/22）讲过原理，用的也是这几步。这一页只讲我们怎么把它做成工程。

02 · 名词

名词小抄

后面会反复出现这些词。看不懂哪个，回来查。

光子包photon packet
模拟里的“一个光子”其实代表一小份能量，可以一点点被吸收，所以叫光子包。
体素voxel
把组织切成很多小立方格，像 3D 的像素。皮肤模型每格 10 微米，膝关节模型每格 1.25 毫米。
吸收系数μa
组织“吃掉”光的本领。数越大，光走同样距离被吸收得越多。血液在 500 nm 很大。
散射系数μs、μs′
光多久被弹开一次。μs′ 是“约化”后的值，把方向偏好也算进去了，文献里常给这个。
各向异性因子g
每次散射偏向原方向的程度。0 表示随便乱弹，接近 1 表示几乎不拐。组织大约 0.9。
光注量率 / 光注量W/cm²、J/cm²
前者是某一点每平方厘米收到多少功率；乘上照射时间就是后者，也就是“剂量”。
仓库 / 分支 / 提交repo / branch / commit
仓库是项目文件夹加完整修改历史；分支是一条独立的修改线，不影响主线；提交是一次存档。
README
每个文件夹里的说明书：这里有什么、怎么用、谁负责、什么时候更新的。
预设preset
一组配好的参数（几何、光学参数、光源），比如“皮肤 500 nm”。换预设就能算别的部位，不用改代码。

04 · 原则

十条整理原则

动手之前先约定原则，遇到拿不准的地方回来对照。每条都附了“为什么”。

  1. 一套引擎，多个预设皮肤和膝关节只是几何、参数和光源不同。算法只写一次，差异变成开关。为什么：改一处 bug，所有模型一起修好。
  2. 参数和代码分开光学参数、尺寸、光源写在单独的配置文件里，每个数字注明出处。为什么：换参数不用懂代码，也能追溯数字从哪来。
  3. 一个函数只做一件事建模、计算、后处理、画图四层分开。计算部分不画图、不写文件。为什么：哪一层出问题，一眼能定位。
  4. 单位只用一种内部统一用毫米，只在输入输出的地方换算并标清楚。为什么：毫米和厘米一混，结果差 10 倍甚至 100 倍。
  5. 物理不变，用测试证明每次改动都要通过能量守恒检查，并和 MATLAB 原结果对比。为什么：“看起来差不多”不算证据。
  6. 速度靠编译，不靠偷工减料逐个光子的循环用 Numba 编译，批次并行跑；固定随机种子，结果可复现。为什么：直接翻译成 Python 会慢约 100 倍。
  7. 仓库只放源代码和小数据安装包、压缩包、论文、大数据集放共享盘，仓库里留链接。为什么：下载快，找东西也快。
  8. 旧代码冻结，不删除MATLAB 原版移到 legacy/，当作对照基准，不再修改。为什么：新版结果有疑问时，有东西可比。
  9. 小步提交，每步都能跑每次提交只做一类事（搬文件、拆模块、加测试），写清楚为什么。为什么：出了问题容易退回，也方便别人审阅。
  10. 每个文件夹都有 README统一格式：是什么、谁负责、里面有什么、怎么用、更新记录、给 AI 的说明。为什么：人能看懂，AI 也能据此整理和更新。

07 · 上手

上手：把代码跑起来

按顺序做。每一步都写了“做完是什么样子”，对上了再往下走。

  1. 装好 git 现在可做

    git 是下载仓库和记录修改的工具。Mac 打开“终端”输入 git --version，有版本号就说明装好了；没有的话系统会提示安装。Windows 从 git-scm.com 下载安装，一路默认即可。

  2. 下载仓库 现在可做

    在终端里进入你想放项目的文件夹，然后运行：

    git clone https://github.com/mmd520520/Monte-carlo.git

    做完是什么样子：多出一个 Monte-carlo 文件夹。仓库比较大（约 860 MB），第一次下载要等几分钟。

  3. 切到工作分支 现在可做

    整理工作在单独的分支上进行，已经推送到 GitHub。运行：

    cd Monte-carlo
git checkout refactor/python-interactive

    做完是什么样子：文件夹里出现 README.md、mcsim/、app/、docs/ 和 legacy/。

  4. 先读 README 现在可做

    打开根目录的 README.md，它会告诉你每个文件夹是什么。每个文件夹里还有自己的 README。

  5. 跑 MATLAB 示例 现在可做

    需要 MATLAB。打开 MATLAB，把当前文件夹切到 legacy/matlab/2demo（皮肤模型），在命令行输入 main 回车。

    第一次先把 main.m 里的 photonCount 改成 2000，几秒钟就能看到结果图。没有并行计算工具箱的话，把 options.useParallel 改成 false。

  6. 用 Python 版和交互界面 现在可做

    安装好 uv（Python 环境管理工具，Mac 上 brew install uv），在仓库根目录运行下面两行，然后用浏览器打开 http://localhost:8501：

    uv sync
uv run streamlit run app/streamlit_app.py

    做完是什么样子：网页左侧是设置，右侧显示组织模型、光分布和剂量。第一次运行要编译约 10 秒。命令行版：uv run mcsim run knee_980nm --dose 10 20 40。

常见问题

MATLAB 提示需要 Parallel Computing Toolbox

在 main.m 里把 options.useParallel = true 改成 false，改成单线程运行，慢一些但结果一样。

跑了很久都没结束

光子数太多了。膝关节模型 10 万个光子要几十分钟。先用 2000 到 10000 个试，确认能跑通再加。

Windows 上中文文件名显示成一串数字

在终端运行 git config --global core.quotepath false，再看一次就正常了。

我改了文件，不确定会不会弄坏别人的东西

只要没有“推送”（push），所有修改都只在你自己的电脑上。拿不准的时候，先问负责人再推送。

08 · 验收

结果怎么才算可信

新版代码要过下面六关。前四关都会写成自动检查，每次改动后自动跑一遍。

检查什么通俗说法通过的标准
能量守恒光子带进去多少能量，最后都要有去处，一点不能多也不能少吸收、反射、透射、侧面离开等全部加起来等于 1，误差小于一亿分之一
物理极限只吸收不散射时，结果要和教科书公式一致符合比尔–朗伯定律；折射率相同时边界不反射
和 MATLAB 对比新旧两版算同一个问题，答案要一样反射、吸收、透射在统计误差范围内一致
可复现同样的设置再算一次，结果一模一样同一随机种子两次结果逐位相同；单线程和并行结果一致
速度普通笔记本上能等得起10 万个光子（皮肤模型）不到 1 分钟
好上手新同事不用人教也能跑起来按 README 从下载到出图不超过 5 分钟
