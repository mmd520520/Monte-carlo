## 两个子文件夹

| 文件夹 | 放什么 | 存在哪 | 谁能看 |
|---|---|---|---|
| [public/](public/README.md) | 可以公开的：重构指南（含网页版）、技术路线调研 | git（公开仓库） | 所有人 |
| `private/` | 敏感材料：内部讨论、分享材料、人员相关的文档 | 只放企业微信微盘；git 已忽略这个文件夹 | 微盘里共享的几位同事 |

## 一份文档该放哪边

按顺序问，任何一条是“是”，就放 `private/`：

| 问题 | 例子 |
|---|---|
| 有没有个人信息或对个人的评价？ | 照片、简历、联系方式、绩效、工作评价 |
| 有没有讲公司的产品规划、客户、商业判断或未公开数据？ | 产品路线、和产品怎么结合、实验原始数据 |
| 有没有公司内部的流程、权限、账号或平台安排？ | 代码平台迁移方案、成员权限 |
| 是不是别人的版权材料？ | 论文 PDF、别人做的 PPT（这类放 `references/` 或 `private/`，都不进 git） |

都不是，而且能帮别人理解或使用代码，就放 `public/`。

**拿不准就先放 `private/`。** 从 `private/` 挪到 `public/` 很容易；反过来，推上公开仓库的东西会留在 git 历史里，删掉文件也收不回。

## 怎么用

- **新文档**：按上表判断放哪边。`private/` 的文件改完同步到微盘。
- **新电脑**：从微盘下载，放到 `project/private/`。
- **推送保护**：`tools/pre-push` 会拦住含 `project/private/` 的提交推到公开仓库，每台电脑装一次（见 [tools/README.md](../tools/README.md)）。

## 给 AI 的说明

- 写任何文档前先判断它属于 `public/` 还是 `private/`。`private/` 的内容不能出现在 `public/`、代码、提交说明或公开网页里。
- 公开文档提到 `private/` 时只写“敏感材料在 `project/private/`，放企业微信微盘”，不列具体文件和内容。
