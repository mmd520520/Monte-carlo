# 07 新项目：从第一天就这样做

> 结论：建仓库、写 README、分公开和私有、装推送检查，第一天花一小时，能省掉后面一整轮“集中再重构”。

## 第一天清单

- [ ] 建仓库，默认**私有**；确认要公开时再改
- [ ] 复制下面的文件夹骨架和 [templates/](templates/README.md) 里的模板
- [ ] 写根目录 README：一句话目标、5 分钟上手、目录地图
- [ ] 写 `AGENTS.md`：给 AI 工具的总说明
- [ ] 写 `.gitignore`：私有文件夹、数据、结果、压缩包、密钥
- [ ] 装推送检查（`tools/pre-push`）
- [ ] 建私有空间（企业微信微盘），和 `project/private/` 对应
- [ ] 第一次提交：`chore: 项目骨架`

## 文件夹骨架

```
新项目/
├── README.md            # 一句话目标、5 分钟上手、目录地图
├── AGENTS.md            # 给 AI 工具的总说明（CLAUDE.md 指向它）
├── .gitignore
├── src/ 或 包名/        # 代码
├── tests/               # 自动测试：先写“怎么算对”
├── docs/                # 技术文档：算法、参数来源
├── project/
│   ├── README.md        # 公开 / 私有的判断规则
│   ├── public/          # 方案、调研：进 git
│   └── private/         # 敏感材料：不进 git，放微盘
├── references/          # 第三方资料：只放清单 README，文件不进 git
├── outputs/             # 运行结果：不进 git，可重新生成
└── tools/               # 一次性脚本、推送检查
```

## 第一周

| 天 | 做什么 |
|---|---|
| 1 | 骨架、README、AGENTS.md；把已有的东西放进来（先集中，不求完美） |
| 2 | 写方案：目标、现状、原则、分阶段计划、验收标准；人审过 |
| 3–4 | 小步实现，每步一个提交；先写测试再写代码 |
| 5 | 补文档；做一个能分享的东西（界面、网页或一页摘要）；发合并请求 |

## 已经有一堆散落文件的项目

按这个项目的路线走（详见 [01_story.md](01_story.md)）：

1. **集中**：放进一个仓库，敏感的先放私有文件夹
2. **盘点**：按“自有 / 第三方 / 数据 / 结果 / 敏感”分类，记录大小和重复
3. **写方案**：原则、目标结构、分阶段计划、验收标准
4. **小步重构**：每步可运行、可验证
5. **交接**：让领域作者核对、接手

## 每周例行

- 合并请求都审过才进 `main`
- README 的“更新记录”跟着改
- 需要决定的事写进方案文档的“待确认”表，决定后写回正文
