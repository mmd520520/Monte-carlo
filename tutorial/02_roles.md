# 02 分工：人做判断，AI 做执行

> 结论：AI 能做的事情变多了，但“定方向、做判断、负责任”还是人的。分工的关键是写清楚谁拍板、谁核对。

## 什么交给 AI，什么留给人

| 交给 AI（起草、执行） | 留给人（判断、负责） |
|---|---|
| 盘点仓库：哪些文件、多大、哪些重复 | 定目标：这个项目要解决什么问题 |
| 按方案重构代码、写测试 | 批准方案和优先级 |
| 写 README、算法说明、调研笔记 | 核对物理、领域知识、业务判断 |
| 生成网页、PPT 框架、Word 文档 | 核对事实：人名、职务、日期、关键数字 |
| 调研开源项目、读文献和源码 | 决定什么能公开、什么不能 |
| 跑对比、找差异的原因 | 对外沟通和承诺 |

一条线：**AI 的结果要能被检查**——有测试、有对照、有出处。不能检查的结论，不采用。

## 一次协作的节奏

1. **人提需求**：一两句话说清楚要什么、给谁用。
2. **AI 先出方案**：盘点现状、列出要改什么、怎么验证。人看过再动手。
3. **AI 小步执行**：每一步都能运行，每一步一个提交。
4. **自动检查**：测试、对照、推送前检查。
5. **人核对**：看关键结果和事实，确认或打回。
6. **记下来**：决定写进 README 或方案文档，而不是只留在聊天记录里。

## 常见问题

- **AI 写的代码谁负责？** 合并它的人负责。所以要能读懂、能验证；读不懂的就让 AI 解释，或者不合并。
- **领域专家要学写代码吗？** 不用精通，但要能读、能跑测试、能用 AI 工具提问（见 [04_distill_and_ai.md](04_distill_and_ai.md)）。
- **会不会越来越依赖 AI？** 依赖的是“写下来的东西”：README、测试、方案。换一个 AI 工具，或者换一个人，都能接着做。
