# 04 让信息留得住、AI 读得懂；用 AI 编程工具

> 结论：把项目知识写进仓库里的文件，而不是留在聊天记录、会议和某个人的脑子里。写清楚了，人能接手，AI 也能接着干。

## 每个文件夹一份 README

固定结构（模板见 [templates/README_TEMPLATE.md](templates/README_TEMPLATE.md)）：

| 部分 | 写什么 |
|---|---|
| 标题 + 一句话 | 这个文件夹是什么 |
| 状态表 | 状态、负责人、最后更新日期 |
| 里面有什么 | 每个文件一行 |
| 怎么用 | 命令或步骤 |
| 更新记录 | 日期 + 改了什么 |
| 给 AI 的说明 | 改这里时要注意什么、要同步更新哪里 |

最后一节是这个项目的特色：它告诉 AI（以及新人）这里的规矩，例如“改了内核要同步更新算法说明”“这里的数字来自实际运行，不要估算”。

## 一份权威来源，其他都从它派生

| 权威来源 | 派生出来的 |
|---|---|
| 重构指南（Markdown） | 网页版、根目录 README、分享 PPT |
| 预设文件（YAML） | 界面上的参数表、导出的配置 |
| 测试 | 验证结果的文档 |

改的时候只改权威来源，再让 AI 把派生的东西同步一遍。两处说法冲突时，以权威来源为准。

## 给 AI 工具的总说明：AGENTS.md

仓库根目录放一份 `AGENTS.md`：项目是什么、怎么运行和测试、约定、哪些文件不能碰。大多数 AI 编程工具开工前会读它：Cursor、Codex 等读 `AGENTS.md`，Claude Code 读 `CLAUDE.md`。本仓库两个都有，内容只写在 `AGENTS.md` 一处（模板见 [templates/AGENTS_TEMPLATE.md](templates/AGENTS_TEMPLATE.md)）。

## 用 AI 编程工具

**国内同事**可以用 Cursor、Trae、通义灵码、CodeBuddy 等 AI 编程工具，具体用哪个以公司批准、网络能稳定访问的为准。用法都一样：

1. **先给上下文**：让它先读根目录 README、AGENTS.md 和相关文件夹的 README。
2. **一次一件小事**：“把皮肤预设的波长改成 600 nm，并加一个测试”，而不是“优化一下代码”。
3. **要它证明**：每个改动都要有测试或对照；让它跑测试并把结果给你看。
4. **看改动再接受**：逐个文件看它改了什么（diff）；看不懂就让它解释。
5. **数字自己核对**：它给出的数字、人名、日期、文献，都要回到原始文件或运行结果确认。

好用的提问方式：

| 想做什么 | 可以这样问 |
|---|---|
| 读懂代码 | “`mcsim/kernel.py` 第 180–250 行对应 MATLAB 的哪一步？” |
| 改参数 | “新增一个 810 nm 的膝关节预设，参数出处写进 source 字段，并让测试通过” |
| 找原因 | “这两个结果差 2.5σ，先判断是统计波动还是系统偏差，给出验证办法” |
| 写文档 | “根据这次提交，更新 tests/README.md 的表格和更新记录” |

不要把私有材料（`project/private/` 里的东西、产品设计细节、未公开数据）粘贴到公司没批准的 AI 工具里，详见 [05_privacy.md](05_privacy.md)。

## 让 AI 帮忙“蒸馏”

项目跑一段时间后，可以让 AI 读全部 README、提交历史和测试，写一页摘要：做了什么、现在什么状态、还有哪些没确认。因为信息都在仓库里，这件事几分钟就能完成，而且有出处可查。
