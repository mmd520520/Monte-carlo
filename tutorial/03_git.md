# 03 新手用 git

> 结论：git 就是“带完整历史的共享文件夹”。记住 5 个概念、5 条命令，就能参与项目。

## 5 个概念

| 概念 | 一句话 | 类比 |
|---|---|---|
| 仓库（repository） | 项目文件夹 + 每一次修改的历史 | 带“版本记录”的共享文件夹 |
| 提交（commit） | 一次有说明的修改快照 | 存档点，写着“改了什么、为什么” |
| 分支（branch） | 一条独立的修改线，不影响主线 | 草稿副本 |
| 合并请求（PR / MR） | 请别人审一下，再把分支合进主线 | 提交审批 |
| 远程（remote） | 服务器上的那份仓库（GitHub 或公司的代码平台） | 云端的那份 |

## 每天 5 条命令

```bash
git pull                      # 1. 开工前：拿到别人的最新修改
git status                    # 2. 看看改了哪些文件
git add 文件名                 # 3. 选出这次要保存的修改
git commit -m "类型: 做了什么"   # 4. 存一个带说明的快照
git push                      # 5. 推到服务器，别人就能看到
```

不想记命令也可以：Cursor、VS Code、GitHub Desktop 都有图形界面，点按钮就行；也可以直接让 AI 编程工具帮你做这几步，但要看它做了什么。

## 提交说明怎么写

格式：`类型: 做了什么`，下面空一行写为什么。

| 类型 | 用在 | 例子 |
|---|---|---|
| `feat` | 新功能 | `feat(app): 中英双语界面` |
| `fix` | 修错 | `fix(pre-push): 检查每一个要推送的提交` |
| `docs` | 文档 | `docs: 算法说明和验证结果` |
| `test` | 测试 | `test: 与加倍法的独立对比` |
| `chore` | 整理 | `chore: 第三方资料移出 git` |

好的提交说明就是项目日志：半年后翻历史，能看懂每一步为什么这么做。

## 分支怎么用

- `main` 是主线，只放审过的东西，**不直接往上推**。
- 做一件事就从 `main` 开一个分支，例如 `feature/head-model`。这个项目的 Python 重构就是在 `refactor/python-interactive` 分支上做的，完成后（2026-11-08）变成了 `main`；原来的 `main` 改名 `legacy`，原样保留。
- 做完发合并请求，至少一个人看过再合进 `main`。

## 用国内网络时

- GitHub 在国内有时慢或连不上。可以用国内能稳定访问的代码平台（例如 Gitee，或公司内部的平台），流程完全一样。
- 搬家时用 `git push --all` 和 `git push --tags` 带上全部历史，不要只复制文件。

## 常见坑

| 坑 | 怎么办 |
|---|---|
| 把大文件、压缩包、安装包提交进去 | 写进 `.gitignore`；已经进历史的要改写历史才能真正删掉 |
| 把密码、密钥写进代码 | 放环境变量或 `.env`（并写进 `.gitignore`）；已经推送的要立刻作废重发 |
| 很多天不提交，一次改一大堆 | 小步提交，一次只做一类事 |
| 直接在 `main` 上改 | 开分支，发合并请求 |
